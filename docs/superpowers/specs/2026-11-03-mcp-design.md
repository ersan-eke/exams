# Phase 3b — MCP server

## Context

Phase 3a put each signed-in user's exams, attempts and grades on the server. Phase 3b exposes that data to
Claude Code or Claude Desktop over MCP, so the host model (on the user's own subscription) can quiz, tutor and
grade from it. Settled roadmap decisions: no server-side LLM key, and no `grade_answer` tool.
3a is merged into local `main` (fast-forward, not pushed). Work happens on the branch `phase-3b-mcp`.

Workflow, per CLAUDE.md: spec `docs/superpowers/specs/2026-11-03-mcp-design.md` (written from this plan) →
`superpowers:writing-plans` → subagent tasks with a review after each → `/code-review high` + `/security-review`
(tokens and auth are touched) → handoff doc + roadmap status → commit.

## Design

### Library + transport
- `uv add mcp`: the official Python SDK v2 (`mcp.server.MCPServer`; v1's `FastMCP` was renamed), checked via Context7.
- `backend/app/mcp/server.py`: `mcp = MCPServer("exam-sim", instructions=...)`.
- `backend/main.py`:
  - Mount the app with `app.mount("/mcp", <auth wrapper>(mcp.streamable_http_app(streamable_http_path="/", stateless_http=True, json_response=True)))`.
  - Add a FastAPI `lifespan` that enters `mcp.session_manager.run()`. The app has none today, and a mounted sub-app's own lifespan never runs.
  - Stateless JSON is enough because no tool calls back into the client.
- `same_origin_writes` passes requests that have no `Origin` header, which is what CLI MCP clients send, so it stays unchanged.

### Auth: personal access tokens
- Migration `<rev>_access_tokens` (autogenerated, revises `2c1ca18c29ed`, additive only; downgrade drops the table): `access_tokens`
  (id UUID, user_id FK cascade, name, token_hash String(64) unique, created_at, last_used_at null). There is no expiry
  and there are no scopes; revoking a token deletes its row.
- A token is `"es_" + secrets.token_urlsafe(32)`. It is shown once and stored as sha256 (reuse `auth._hash`, as `sessions` does).
- Routes in `app/api/auth.py`, behind `current_user` (cookie): `GET /api/tokens`, `POST /api/tokens {name}` → `{id, token}`,
  and `DELETE /api/tokens/{id}`, which returns 404 for another user's token.
- `app/mcp/auth.py` is a pure-ASGI wrapper around the mounted app:
  - It reads `Authorization: Bearer` and looks up the hash.
  - On a miss it returns 401 JSON with `WWW-Authenticate: Bearer`.
  - On a hit it sets a `ContextVar[uuid]` for the tools and bumps `last_used_at`.
  - `shortcut:` this skips MCP OAuth 2.1, which one-click claude.ai connectors need; add it when publishing as a connector.

### Tools
Plain functions `(db, user_id, ...)` live in `app/mcp/tools.py`; `server.py` has thin `@mcp.tool()` wrappers that open a
`SessionLocal` and read the ContextVar.
- Every query filters by `Exam.user_id == user`. A foreign or unknown id gives the same "not found" error.
- A subtask is addressed as `"<exam_id>/<subtask key>"`.
- Max points: `point_overrides[key]` if present, else `subtask.points`.

The tools:
- **`list_subjects()`** returns the courses with exam count, graded-attempt count and score share.
- **`progress(subject?)`** returns, per subject:
  - the score share per task title, weakest first;
  - the last 5 graded attempts' score share (the trend);
  - the exams never attempted.

  It is built from the graded handed-in attempts: `coalesce(grades.over, grades.main)` ÷ max points.
- **`find_tasks(subject, query?, filter?)`**:
  - `filter` ∈ `unattempted | scored_below:<0..1> | has_solution`.
  - `query` is an `ILIKE` match on subtask text, label and task title.
  - It returns at most 20 rows: id, exam title, label, points, the first 200 characters of the text, and the last score.
  - `shortcut:` text match; Phase 4 vector search replaces it.
- **`get_task(subtask_id, include_solution=false)`** returns the text, task context, MC options and points, plus the crop
  PNGs as `Image` content from `exam_dir(id)/blank/crops/`.
  - The solution part is the `solution_text` / `mc_key`, the exam's `ink/crops`, or the linked solution exam's crops
    (via `solution_for`). It is returned only when `include_solution=true`.
  - The tool description tells the host to fetch the solution only after the user has answered.
- **`my_history(subtask_id)`** returns every handed-in answer to that subtask, newest first: date, typed text, points/max,
  comment, and LLM feedback if any.
- **`record_practice(subtask_id, answer, points, feedback)`** writes a **handed-in, graded attempt** that contains only that
  subtask's task.
  - It has `includedTaskIds=[task key]`, a typed answer, `grades.main=points` clamped to `0..max`, `comment=feedback`,
    `gradedAt=editedAt=now`, and `fresh=false`.
  - It goes through the existing `write_attempt` (`app/db/attempts.py`), so 3a sync pulls it to every device, and Results
    and Statistics show it with no frontend change.
  - Verify while building that a single-task attempt with untouched other subtasks renders correctly in Results.
- **`set_points(subtask_id, points)`** sets `point_overrides[key]` and bumps `edited_at`, so sync pulls it.

Crops go inline as images in `get_task`. The roadmap's separate `exam://` resource is dropped because hosts show tool images directly.

### Frontend
- `SettingsPanel.vue`, when signed in, gets an "MCP access" section:
  - a name field and a Create button;
  - the new token, shown once, with a copy button and a ready-to-paste `claude mcp add` line;
  - the token list with Revoke.
- Fetch calls in a small `lib/tokens.ts`, following the existing API helpers.

### Docs
- README "Use with Claude": `claude mcp add --transport http exam-sim http://localhost:8000/mcp --header "Authorization: Bearer es_…"`,
  the Claude Desktop config, and an example session ("Quiz me on GRNVS, focus on what I'm bad at" → progress →
  find_tasks → get_task → answer → get_task(include_solution) → record_practice).

## Verification
- `uv run pytest`:
  - Tool functions run on a seeded exam and attempts:
    - another user's ids → not found;
    - the solution is hidden unless asked for;
    - `record_practice` clamps points and the attempt then appears in `GET /api/sync`;
    - `set_points` bumps `edited_at`;
    - `progress` and `find_tasks` filters return the expected rows.
  - HTTP through `TestClient` (including the lifespan):
    - `/mcp` without a token → 401;
    - a revoked token → 401;
    - a valid token → `tools/list` lists 7 tools, and `get_task` returns image content.
  - Token routes: create/list/revoke, another user's → 404, and only the hash is stored.
- `npx vitest run` + `npm run type-check`: the token section spec.
- Manual: create a token in the app, run `claude mcp add …`, ask Claude Code to "quiz me on <subject>", and check that the
  practice attempt shows up in the web app.
