# Phase 3a — Auth + Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two-way sync of exams and handed-in attempts between all devices of one signed-in account.

**Architecture:** IndexedDB stays the working copy. `lib/db.ts` stamps `editedAt` and records dirty ids in a
localStorage outbox; `lib/sync.ts` pushes dirty records (`PUT /api/exams/{id}`, `PUT /api/attempts/{id}`) and
pulls changes (`GET /api/sync?since=`). The server keeps the newer `edited_at` per record.

**Tech Stack:** FastAPI, SQLAlchemy 2, Alembic, Postgres, pytest; Vue 3, Pinia, idb, vitest + fake-indexeddb.

**Spec:** `docs/superpowers/specs/2026-11-02-sync-design.md`

## Global Constraints

- Backend: uv only (`uv run …`, `uv add`), tests `uv run pytest` in `backend/` (DB `examsim_test`). Frontend: `npx vitest run` in `frontend/`.
- New routes require sign-in via `current_user` (401). Writes stay behind the existing same-origin check.
- Columns for joined/filtered/summed, JSONB for whole values. `exams.id`/`attempts.id` are client-made.
- Never commit PDFs or crops. No LLM key is stored or logged.
- Deliberate simplifications carry `# shortcut: <limit>, <when to upgrade>` (or `// shortcut:`).
- No PDFs in tests: use `SAMPLE` from `backend/tests/test_db.py` and `signed_in()` from `backend/tests/test_auth.py`.
- Out of scope: running attempts on the server, real-time push, field-level merge, deletes/tombstones, per-account local data.

## Wire format (decided here, used by every task)

camelCase JSON, times as epoch ms numbers, maps keyed by subtask key (`"A2b"`). It mirrors the client types so the
client sends its records nearly as-is.

- **ExamMeta:** `{id, title, hasInk, hidden, subject: str|null, pointOverrides: {key: number}|null,
  rubrics: {key: RubricLine[]}|null, solutionFor: uuid|null, fingerprint: str|null, createdAt, editedAt}`.
- **ExamPut** = ExamMeta + optional `structure` (ExamStructure JSON), `images`, `solutionImages`
  (`{name: base64}`).
- **AttemptWire:** client `Attempt` without `view`: `{id, examId, solutionExamId, status, fresh, startedAt,
  timeLimitMs, includedTaskIds, attendanceAt, attendanceDone, mcRule, extended, answers, snapshot, handedInAt,
  time, grades, gradedAt, editedAt}`; `answers`/`snapshot` values `{mode, parts, done, ticks}`, `time` values
  `{main, over}`, `grades` values `{main?, over?, comment?, marks?, llm?}` (numbers as floats, not strings).
- **SyncOut:** `{cursor: ISO-8601 str, exams: ExamMeta[], attempts: AttemptWire[]}`.

## Review Focus

1. A record from an older app version without `editedAt` (or with `hidden`/`subject` missing) — must push as `editedAt: 0`/defaults, not 422. Test in Task 5.
2. An attempt whose `solutionExamId` names a solution exam that hasn't been pushed yet — push must push that exam and retry, not drop the attempt. Test in Task 6.
3. Two pushes of the same attempt in quick succession (debounce + visibility trigger) — `sync()` must not run twice at once. Test in Task 6.
4. The signed-in user's own anonymous upload (uploaded before signing in) — PUT exam claims it, `GET /api/exams/{id}` then still works for them. Test in Task 2.
5. Subject renamed only in case (`grnvs` → `GRNVS`) — stays one course. Test in Task 1.

  - `pulled: Ref<number>` — incremented after a pull that wrote at least one record; `lastPulled: { exams: string[], attempts: string[] }` ids written by the last pull.

  - `on need_exam pushes the exam (and the solution exam) then retries the attempt once`.
