# Phase 4: RAG "Ask" + slides per subject

## Context

Roadmap Phase 4 (`docs/roadmap.md`), after Phase 3b (`docs/2026-11-04-mcp-handoff.md`). The user wants to add slides/scripts per
subject, ask questions answered from slides + past exams with page citations, and get "similar tasks" scoped to one subject.
Vector search then replaces the two text-match shortcuts: client `similarSubtasks` (`frontend/src/lib/grading.ts:~257`) and
MCP `find_tasks` ILIKE (`backend/app/mcp/tools.py`). Settled decisions stay (own LLM key per request in `X-LLM-Key`, never stored;
host model tutors in MCP; no new `grade_answer`). One phase = one session: spec -> plan -> subagent-driven build -> `/code-review high`
+ `/security-review` (uploads, keys) -> verify -> handoff doc.

## Decisions (Claude's calls; confirm in the spec, the user asked for no questions)

- **Embeddings: local multilingual model via `fastembed` (ONNX, no torch)**, e.g. `paraphrase-multilingual-MiniLM-L12-v2`, 384 dims
  (exams are DE + EN). Reason: the worker has no user key and Anthropic offers no embeddings; local keeps "key never stored" intact and
  costs nothing. Verify the model name/dims with Context7 before coding. `shortcut:` model is fixed; changing it needs a re-embed migration.
- **Answer generation** uses the user's key through the existing provider adapters. Output is structured `{answer, cited: [chunk_id]}` so
  citations are validated server-side (drop ids not in the retrieved set). Needs the adapters' hard-wired `llm_schema()` parameterised
  (schema + system + content passed in) instead of a second adapter family.
- **Retrieval:** Postgres full-text (`tsvector`, `simple` config for DE+EN) + pgvector cosine, merged by RRF, always `WHERE course_id = ...`
  and `user_id = ...`.
- **Slides need sign-in** (server-side); signed out shows a quiet hint.
- No new job table: add `jobs.kind`.
- **Material = many PDFs per subject.** A document is one chapter (title defaults to the filename, editable) with a `position` for
  ordering. Kinds: `slides | script | exercises` (tutorial exercises count as material for Ask and for grading context).
  `documents.course_id` is nullable: a PDF can be uploaded unassigned and **assigned to a subject later** (`PATCH /api/documents/{id}`
  `{subject?, title?, position?}`). Chunks do not copy `course_id`; search joins `documents`/`exams` for it, so reassigning is one row update
  and retrieval ignores unassigned documents.
- **Viewer: no new dependency.** Keep the original PDF (`doc_dir(id)/file.pdf`, served inline by `GET /api/documents/{id}/file`, owner-checked)
  and open it in the browser's built-in viewer with `#page=N` inside an `<iframe>` (route `/material/:id?page=N`, with chapter title,
  page number and prev/next chapter links). This replaces the planned per-page PNG rendering and its route. Check that no
  `X-Frame-Options: DENY` is set for same-origin responses.
- **Cheap prompts.** Retrieved material goes into prompts as text only: top 3 chunks, hard cap ~1500 chars total, each tagged
  `[c12] Chapter 3, p. 14`. No page images. In Ask the model cites ids; the server drops unknown ids; the app turns a citation into a
  link to the viewer (and an optional collapsed text snippet).
- **"Read this again" links, with or without a solution, fetched on click.** A button under a subtask calls
  `POST /api/materials/lookup {subtask text, solution text?, subject}`; the server runs `search` (no LLM call, no tokens) and returns the
  top 2 chunks above a minimum score as `[{document_id, title, page}]`. Grading itself is not touched, so it stays fast and the embedding
  model only loads in the API process when someone asks. Links come from retrieval, not the model, so nothing needs validating. Only in `own_solution` mode (no solution sheet) is the same capped text block also put
  into the prompt as context. It replaces the image `references` for similar tasks (text snippets of same-subject solved subtasks,
  same cap). With a solution present the prompt gets no material at all.

## Steps (each a small TDD task with a review)

1. **Infra + migration.** `compose.yaml` image -> `pgvector/pgvector:pg18` (recreate the db volume / `down -v` note in the handoff).
   `uv add pgvector fastembed`. One Alembic migration (after head `7cea61f142c4`): `CREATE EXTENSION vector`; `documents`
   (id, user_id, course_id NULL, kind `slides|script|exercises`, title, position, filename, sha256, page_count, UNIQUE(user_id, sha256)); `chunks` (id, document_id NULL,
   subtask_id NULL, user_id, page, text, `tsv` generated tsvector + GIN, `embedding vector(384)` + HNSW cosine; exactly one of document_id/subtask_id);
   `jobs.kind` (`exam` default | `document`), `jobs.document_id`; relax `jobs.role` CHECK/nullable for documents. Models in
   `backend/app/db/models.py` with the existing `choice/created/updated` helpers. Test DB already runs `alembic upgrade head`, so the
   extension must work on the compose image.
2. **Embedding + chunking module** `backend/app/rag/{embed,chunk}.py`. Chunk slides by page (`pipeline.extract.extract` -> `page.body`
   lines, reuse as-is); scripts by heading with a size cap; exam subtasks from stored `Subtask.text` / `solution_text` (already structured,
   no PDF needed). Lazy-load model once per process; embed in batches.
3. **Document ingestion in the worker.** `POST /api/documents` (multipart `file`, optional `subject`, `kind`, `title`; `current_user`; `%PDF-`
   check, size cap like `upload_exam`; dedupe on sha256 -> return existing). One request per file; the UI uploads several files in a
   row and appends them with increasing `position`. Worker `process_document` branch in `worker/main.py`: extract -> chunk -> embed ->
   insert, then move the PDF to `doc_dir(document_id)/file.pdf` (new in `core/storage.py`) instead of unlinking it (the exam path keeps
   its unlink). `GET /api/documents?subject=` (also `?unassigned=1`), `PATCH /api/documents/{id}` (assign/reorder/rename),
   `DELETE /api/documents/{id}` (owner only, removes chunks + file), `GET /api/documents/{id}/file` (owner-checked, inline PDF).
   Progress reuses `GET /api/jobs/{id}/events`. Exercises are chunked like slides (by page); `shortcut:` no exercise/solution pairing.
4. **Exam chunks.** Index subtask chunks when an exam is stored (`worker.process` / sync `PUT /api/exams`, through `db/exams.to_rows`
   path) and backfill existing exams with a one-off CLI (`python -m app.rag.backfill`). Idempotent (replace chunks for the subtask).
5. **Search + Ask API.** `app/rag/search.py`: `search(db, user_id, course_id, query, kinds, k)` hybrid + RRF. `POST /api/ask`
   (`current_user`, `X-LLM-Key` required -> 400 `no_key`, reuse `grade_limiter`-style limiter and body cap) -> SSE or single JSON with
   `{answer, citations:[{chunk_id, document_id|exam_id, title, page}]}`. `GET /api/similar?subtask=` (subject-scoped, excludes own exam,
   solved exams first). Prompt in `backend/app/rag/prompt.py`; answer only from provided chunks, say so when nothing relevant.
   `POST /api/materials/lookup` (see above) serves the on-click links under a subtask in Results (frontend: a "Where to read this" button
   in `GradingRow.vue`, result cached per subtask in memory). Grading: `/api/grade` gets an optional `subtask_text`/`subject`; when
   signed in and no solution is attached it runs `search` and appends the capped text block to the prompt. Search failure or no hit
   means no block, never a failed grade.
6. **Replace the shortcuts.** MCP `find_tasks(query)`: use `search` over subtask chunks when `query` is set (keep filters; fall back to
   ILIKE for rows without embeddings). Grading: material text from step 5 replaces the image `references` when signed in; the Jaccard
   `similarSubtasks` stays as the signed-out fallback. Remove the `shortcut:` comments only where actually replaced.
7. **Frontend.** `lib/documents.ts` + `lib/ask.ts` (pattern: `lib/tokens.ts`). Router: `/ask` -> new `AskView.vue` (subject picker, chapter
   list ordered by `position` with rename/reorder/delete, a multi-file `PdfDropZone` for slides/script/exercises, an "Unassigned" list
   with a subject picker to assign later, question box, answer whose citations read "Chapter 3, p. 14" and link to the viewer, optional
   text snippet). New `MaterialView.vue` at `/material/:id?page=N` (iframe viewer with title, page, prev/next chapter). Grading rows in
   `GradingRow.vue` show `sources` as the same links. `MyExamsView.vue`: per-subject "Add material" control in the `FoldBar` header with
   the subject preset. Signed-out: hint "sign in to add material". Key from `useSettingsStore`; no key -> disabled with hint.
8. **Tests.** Backend: migration/extension, chunking (stored `ExamStructure` / in-test PDF), RRF ordering with fake embeddings
   (monkeypatch `embed` to deterministic vectors so tests don't download the model), subject isolation (user A / subject X never sees
   Y or another user's rows), ask with the mocked adapter (citation filtering, missing key 400, key not logged), ownership 404s,
   file route ownership, assign-later (unassigned docs are not searchable, searchable right after PATCH), several chapters in one subject
   with ordering, grading prompt size (no material when a solution exists; capped text otherwise) and the lookup endpoint returns links in both modes (empty list when there is no material). Frontend vitest: `AskView`,
   `MaterialView`, `MyExamsView` material control, `ask.ts`. Pipeline smoke is untouched
   unless `pipeline/` is edited.
9. **Wrap-up.** `ruff check . && ruff format .`; update `docs/roadmap.md` status, `docs/mcp.md` (find_tasks search), CLAUDE.md run notes
   (pgvector image); write `docs/<date>-rag-handoff.md` (done / not done / decisions).

  pulls similar tasks from the same subject only.

## Not in scope / risks

Voyage or other hosted embeddings, non-PDF scripts, OCR for scanned slides (scanned pages are skipped, noted in the handoff), streaming
answers. Risks: first run downloads the embedding model (~120 MB); the existing dev DB volume must be recreated for pgvector; the
`jobs.role` constraint change touches the exam path, so the existing worker/API tests must stay green.
