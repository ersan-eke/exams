# MCP Server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let Claude Code / Claude Desktop quiz and grade the user from their own synced exam data over MCP, authenticated with personal access tokens.

**Architecture:** The official MCP Python SDK v2 (`MCPServer`) runs stateless streamable HTTP, mounted into the FastAPI app at `/mcp` behind a small ASGI bearer-token wrapper. That wrapper resolves an `access_tokens` row to a user id held in a `ContextVar`. The tool logic lives in plain functions `(db, user_id, ...)` in `app/mcp/tools.py`, so it can be tested without the protocol. Practice results are written as ordinary handed-in attempts through the existing `write_attempt`, so Phase 3a sync carries them to every device.

**Tech Stack:** FastAPI, SQLAlchemy 2, Alembic, Postgres, `mcp` (Python SDK v2), Vue 3 + Pinia, vitest.

**Spec:** `docs/superpowers/specs/2026-11-03-mcp-design.md`

## Global Constraints

- Backend deps via `uv add` only; run everything with `uv run` from `backend/`.
- SDK v2 names: `from mcp.server import MCPServer`, `from mcp.server.mcpserver import Image`, test client `from mcp import Client`. Check `/modelcontextprotocol/python-sdk` in Context7 for anything else.
- Every tool query filters by `Exam.user_id == <token's user>`. A foreign id and an unknown id give the same error text: `"not found"`.
- A subtask id on the wire is `"<exam uuid>/<subtask key>"`, e.g. `"3f2c…/A2b"`.
- Max points of a subtask = `exam.point_overrides[key]` if present, else `subtask.points`; `None` when both are missing. `shortcut:` the client's MC point split (`maxPoints` in `frontend/src/lib/scoring.ts`) is not mirrored server-side; such subtasks count as max unknown.
- A token is `"es_" + secrets.token_urlsafe(32)`, stored only as `auth._hash(token)` (sha256 hex). The plaintext is returned once, by the create route.
- Bearer auth skips MCP OAuth 2.1. The wrapper carries `# shortcut: no MCP OAuth 2.1 (needed for one-click claude.ai connectors); add it when publishing as a connector`.
- Deliberate simplifications carry a `shortcut:` comment (CLAUDE.md).
- Never log tokens or the `Authorization` header.

## Review Focus

1. **Practice attempts and sibling subtasks.** A practice attempt includes one whole task (`includedTaskIds` is task-level), so unpracticed sibling subtasks score 0 in Results/Statistics. `record_practice` therefore takes a list of results for one task. Its tool description tells the host to practice whole tasks, and the tool sets `grades` only for the subtasks it was given. Test: a two-subtask task with one result → the attempt has exactly one grade, `includedTaskIds == [task key]`.
2. **Revoked or deleted token mid-session.** Every request re-checks the hash (stateless), so a revoked token gets 401 on its next call. Test in Task 2.
3. **Mounted path.** Clients POST to exactly `/mcp` (no trailing slash) and expect no redirect, because POST redirects are not reliably followed. Test in Task 2: `POST /mcp` answers without a 307.
4. **DNS-rebinding protection.** The SDK auto-enables Host checking for `host="127.0.0.1"`, which would reject `Host: localhost:5173` coming through the Vite proxy. Pass `transport_security=TransportSecuritySettings(enable_dns_rebinding_protection=False)` with a one-line comment: bearer auth protects it, and a browser page cannot attach the token. Test: a request with `Host: localhost:5173` and a valid token succeeds.
5. **Points outside the range.** `record_practice` points < 0 or > max are clamped to `0..max`. With max unknown, only `≥ 0` is enforced. `set_points` rejects values ≤ 0 or > 1000. Tests in Task 4.

### Task 3: Read tools: progress, find_tasks, get_task, my_history

**Files:**
- Modify: `backend/app/mcp/tools.py`, `backend/app/mcp/server.py`
- Test: `backend/tests/test_mcp_tools.py`

**Interfaces:**
- Consumes: `NotFound`, `list_subjects`, `current_user_id`, `mcp` (Task 2); `from_rows`, `to_rows` (`app/db/exams.py`); `exam_dir` (`app/core/storage.py`); `read_attempt`/`subtask_keys` (`app/db/attempts.py`).
- Produces (in `tools.py`):
  - `resolve(db, user_id, ref: str) -> tuple[Exam, Task, Subtask]`: parse `"<uuid>/<key>"`. A bad uuid, a missing row or another user's exam all raise `NotFound("not found")`.
  - `max_points(exam, sub) -> float | None` (the Global Constraints rule).
  - Shares count only graded subtasks of handed-in attempts with a known max. A subtask's score is `coalesce(grade.over, grade.main)`.
  - `progress(db, user_id, subject: str | None) -> list[dict]`: per course (all of them, or the one whose name matches case-insensitively; an unknown name raises `NotFound`), `{subject, score_share, tasks: [{exam, task, score_share}] weakest first, recent: [{handed_in_at, score_share}] last 5 newest first, unattempted: [{exam_id, title}]}`. Hidden exams and solution exams (`is_solution` or `solution_for` set) are excluded everywhere.
  - `find_tasks(db, user_id, subject: str, query: str | None, filter: str | None) -> list[dict]`. `filter` ∈ `None | "unattempted" | "scored_below:<x>"` (0 ≤ x ≤ 1) `| "has_solution"`, else `ValueError`. `query` is an ILIKE `%q%` on subtask text, subtask label and task title, with `%`/`_` escaped. Each row is `{id, exam, task, label, points, text: first 200 chars, last_score_share}`, ordered by exam title then position, at most 20 rows. `has_solution` = non-empty `solution_text`, or an `mc_key`, or the exam `has_ink`, or an attempt of this exam has a `solution_exam_id`. `# shortcut: text match; Phase 4 vector search replaces it`.
  - `get_task(db, user_id, ref, include_solution: bool) -> tuple[dict, list[Path]]`. The dict holds `{id, exam, task, task_context_text, label, text, points, mc_options: [text]}`, plus `solution: {text, mc_key}` only when `include_solution` is true. The paths are `exam_dir(exam.id)/"blank"/"crops"/<region.image>` for the subtask's regions that exist on disk. With `include_solution`, add `ink/crops/<same names>` when `has_ink`, else the crops of the latest attempt's `solution_exam_id` exam for that subtask key, if owned.
  - `my_history(db, user_id, ref) -> list[dict]`: handed-in attempts of the user that contain the subtask, newest first: `{attempt_id, handed_in_at (ISO), answer_text (joined parts' text), points, max, comment, llm_feedback}`.
- Server wrappers: `get_task` returns `[json text, *Image(path=p)]` (a list of content). The docstrings tell the host when to call each tool; the `get_task` docstring says to call it with `include_solution=true` only after the user has answered. `NotFound`/`ValueError` surface as tool errors carrying the message.

### Task 4: Write tools: record_practice, set_points

**Files:**
- Modify: `backend/app/mcp/tools.py`, `backend/app/mcp/server.py`
- Test: `backend/tests/test_mcp_tools.py`

**Interfaces:**
- Consumes: `resolve`, `max_points` (Task 3); `write_attempt`, `subtask_keys` (`app/db/attempts.py`); `AttemptWire`, `AnswerWire`, `GradeWire`, `TimeWire` (`app/db/sync.py`).
- Produces `record_practice(db, user_id, results: list[dict]) -> dict`:
  - Each result is `{subtask_id, answer: str, points: float, feedback: str}`, 1–20 of them, and all must be in the same exam and task, else `ValueError("one task per call")`.
  - It builds an `AttemptWire` with these values:
    - `id=uuid4()`, `exam_id`, `status="handed_in"`, `fresh=False`;
    - `started_at = handed_in_at = graded_at = edited_at = now ms`, `time_limit_ms=0`;
    - `included_task_ids=[task.key]`, `attendance_at=None`, `attendance_done=False`;
    - `mc_rule = task.mc_rule or exam.mc_rule or {"kind":"all_or_nothing"}`, `extended=False`, `snapshot=None`;
    - `answers={key: AnswerWire(mode="type", parts=[{"text": answer, "strokes": []}])}`;
    - `time={key: TimeWire(main=0, over=0)}`;
    - `grades={key: GradeWire(main=clamped, comment=feedback)}`.
  - It then calls `write_attempt` and commits. Return `{attempt_id, points: [{subtask_id, points, max}]}`.
- Produces `set_points(db, user_id, ref, points: float) -> dict`: requires `0 < points ≤ 1000`, else `ValueError`. Set `exam.point_overrides = {**(existing or {}), key: points}` (reassign the dict so the JSONB change is saved), then `exam.edited_at = func.now()` and commit. Return `{subtask_id, points}`.
- Server wrappers: the `record_practice` docstring says to call it once per task after grading the user's answers against the solution (from `get_task(include_solution=true)`), and that the result shows up in the user's app. `set_points` is for fixing a subtask's max points when the printed value is wrong.
